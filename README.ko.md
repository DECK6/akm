# AKM — Agent Knowledge Management (한국어 안내)

> 기본 문서는 [README.md](README.md) (영문)입니다. 시스템 파일(99-system, adapters, templates)은 영어가 기본이며, 레이어에 저장하는 노트는 어떤 언어든 무방합니다.

**자신의 분야에 맞는 온톨로지와 LLM 위키를 함께 만들고, 이후 탐색·확장·연결 보완·검증·재개까지 운영하는 종합 지식관리 스킬입니다.**

사용자는 **`$akm` 하나**로 요청하고, 진입점이 14개 전문 역할을 연결합니다. 기존 공개 AKM의 분류·저장 구조는 사용자별로 선택하는 기반 모듈로 포함됩니다. 지식은 Markdown과 원본 파일로 남으며 DB·서버·유료 API·gstack 설치가 필수는 아닙니다.

[스킬 15개와 상세 사용법](skill-suite/README.md) · [실행 가능한 예제](skill-suite/examples/reading-club/index.md) · [검증 기록과 한계](skill-suite/VALIDATION.md)

## 설치와 시작

Codex에서는 Python 3.10+로 설치할 수 있습니다.

```sh
git clone https://github.com/DECK6/akm.git
cd akm
python3 skill-suite/akm/scripts/install.py
```

기본 설치 경로는 `CODEX_HOME/skills`, 설정하지 않았다면 `~/.codex/skills`입니다. 기존의 같은 이름 스킬을 덮어쓰지 않습니다. 심볼릭 링크 방식이므로 클론 폴더를 유지하세요. 다른 호스트의 등록 방식과 설치 옵션은 [상세 안내](skill-suite/README.md#로컬-설치)를 참고하세요.

설치 후 아래처럼 요청합니다. 호스트가 자연어 요청에서 자동으로 스킬을 선택하지 않으면 `$akm`을 붙이세요.

> akm 구축 시작해줘
>
> 온톨로지 구축 시작해줘
>
> llm wiki 구축 시작해줘

세 요청 모두 **같은 시작 인터뷰**를 불러옵니다. 분야의 실제 사례·판단·용어·조건·예외를 관련 질문 묶음으로 파고들고, 답변에서 새로운 갈래가 나오면 더 탐색합니다. 사용자가 더 생각나지 않는다고 하거나 정리·중단·생략을 요청하면 그에 맞춰 다음 단계로 넘어갑니다.

인박스가 필요한지, 지식층을 얼마나 깊게 만들지, 기억·절차·실행·평가 같은 운영층은 어디까지 필요한지도 인터뷰로 정합니다. 이어 사용자 질문 또는 에이전트 추천을 바탕으로 **실제 설명이 담긴 첫 위키 3편**과 연결된 의미 모델을 만듭니다. 후속 확장에서는 필요한 기존 노트를 보강하거나 새 노트를 추가합니다.

이 클론에서 설치했다면 저장소 루트에서 업데이트합니다.

```sh
git pull --ff-only
python3 skill-suite/akm/scripts/install.py
```

## 온톨로지와 위키가 함께 바뀝니다

| 구성 | 역할 |
|---|---|
| AKM 구조 | 원문·지식·맥락·운영 기록을 사용자에게 필요한 범위로 배치 |
| 온톨로지 | 개념·대상·관계의 의미와 성립 조건·예외·근거를 정의 |
| LLM 위키 | 같은 개념과 주장으로 사용자의 질문에 답하는 설명을 합성 |
| 지속 운영 | 빈틈 탐색·자료 편입·확장·연결 보완·검증·재개 |

온톨로지와 위키는 개념·주장·출처 ID, 정본 정의, 변경 이력을 공유합니다. 위키에서 발견한 예외는 모델로 돌아가고, 모델의 조건 변경은 설명·예제·답변에도 반영됩니다. 폴더 분류나 링크 수만으로 의미 관계를 판단하지 않습니다. 자세한 기준은 [연결된 지식 규약](skill-suite/akm/skills/akm/references/linked-knowledge.md)에 있습니다.

## 처음 만든 이후에도 같은 진입점을 씁니다

| 요청 | 진행하는 작업 |
|---|---|
| “이 자료를 기존 지식에 반영해줘” | 원문 보존 → 기존 주장과 비교 → 모델·위키 갱신 → 재검증 |
| “다음에 무엇을 조사해야 할까” | 못 답한 질문·약한 근거·반례에서 조사 후보 제안 |
| “지식을 알아서 확장해줘” | 허용된 범위와 예산 안에서 탐색·편입·보강·연결·검증 실행 |
| “빠진 연결을 보완해줘” | 고립 노트·모델 대응 누락을 찾고 근거가 있는 연결 추가 |
| “완결성을 검사해줘” | 구조와 함께 질문의 답·조건·반례·미확인·근거를 검토 |
| “새로운 분야도 시작하자” | 새 분야 인터뷰와 별도 모델·위키·상태를 추가하며 기존 분야 보존 |
| “이어서 진행해줘” | 실제 파일·리비전·미완료 작업을 확인하고 중복 편입 없이 재개 |

자동 운영은 범위를 정해 위임할 수 있습니다.

> $akm 도시 정원 지식을 확장해줘. 이 공간의 자료만 사용해서 최대 3개 작업을 진행하고, 빠진 연결과 바뀐 답을 검사한 뒤 남은 작업을 저장해줘.

현재 에이전트가 실제 변경과 검증을 수행하고 다음 작업을 기록합니다. 새 근거가 없으면 변경 없음으로 마칠 수 있습니다. 스킬 설치만으로 백그라운드 서비스가 시작되지는 않습니다. 정기 실행은 요청한 호스트 스케줄러에 등록하고 활성화를 확인해야 합니다. [지속 운영 규약](skill-suite/akm/skills/akm/references/lifecycle.md)에 범위·예산·중단·재개 기준이 있습니다.

## 지식 검증과 그 범위

`knowledge.py`는 ID·참조·관계 종류·출처·파일 최신성 검사(`lint`), 선언한 질문의 검증 기록(`coverage`), 다음 작업 후보(`frontier`), 변경 영향(`impact`)을 읽기 전용으로 확인합니다. [독서모임 예제와 실행 명령](skill-suite/README.md#실행-가능한-지식-검사)으로 바로 확인할 수 있습니다.

**완결성은 선언한 범위의 질문에 현재 근거로 답할 수 있는지**를 뜻합니다. 린트 통과만으로 사실 정확성을 증명하지 않습니다. 실제 원문·설명·조건·모순은 의미 검수에서 확인하며, 검사 연결표 밖의 파일과 OWL/RDF 추론은 별도 검사가 필요합니다.

[검증 기록](skill-suite/VALIDATION.md)은 단위 검사와 가상 인터뷰·후속 규칙 갱신·연결 보완·변경 없는 재개 시험을 구분합니다. 모든 분야나 에이전트에서 성능을 보장하는 결과는 아닙니다.

## 기존 Markdown 코어

공개 AKM 코어를 그대로 쓰거나, `akm-structure` 인터뷰로 필요한 층만 선택할 수 있습니다. 기존 공간의 INDEX·ROUTER·SCHEMA·LOOP와 로컬 규칙은 유지합니다. 아래는 코어의 기본 저장 역할이며, 새 공간에 모든 폴더를 강제하지 않습니다.

| 레이어 | 폴더 | 기준 |
|---|---|---|
| Source | `10-sources/` | 원본 보존, 수정 금지 |
| Knowledge | `20-knowledge/` | 누구에게나 참인 재사용 지식 |
| Context | `30-context/` | 이 사용자·프로젝트에서만 참인 것 |
| Operational Memory | `40-memory/` | 매 세션 먼저 알아야 할 짧은 포인터 |
| Procedural | `50-procedures/` | 반복 실행 절차 |
| Action | `60-actions/` | 재현·검증·인수인계에 필요한 기록만 |
| Evaluation | `70-evaluation/` | 실패 패턴·품질 기준 — 실패가 학습이 되는 곳 |

7개 레이어는 로딩 관점에서 3개 저장소로 묶입니다:

- **Memory** (`40`) — 매 세션 항상 로드, 포인터만
- **Brain** (`50`+`60`+`70`) — 작업할 때 읽음: 절차, 결정, 실패 패턴
- **Vault** (`10`+`20`+`30`+`80`) — 지식이 필요할 때 읽음: 원본, 지식, 맥락, 산출물

레이어 = 저장 의미론(무엇을 어디에), 저장소 = 로딩 동작(언제 읽는가). 자기 brain/메모리가 이미 있는 에이전트는 `adapters/custom/` 참조 — 네이티브는 그대로 두고 포인터로 연결합니다.

운영 루프: **Ingest → Classify → Compile → Contextualize → Execute → Verify → Learn Back**. 마지막 Learn Back(실패를 원인 레이어 수정으로 되돌리기)이 없으면 AKM이 아닙니다.

검증은 위험도에 따라 Tier 0(일회성 답변)부터 Tier 3(고위험 claim ledger)까지 적용합니다. DEER 벤치마크에서 가져온 7개 평가 축—요청 충족, 분석 건전성, 구조, 형식, 윤리·안전, 정보 충분성, 정보 무결성—과 Task Evaluation Guidance, claim 검증을 `99-system/VERIFICATION.md`에서 AKM의 Verify/Learn Back 절차로 연결합니다.

## Markdown 코어를 직접 사용하기

1. 클론 후 `adapters/`에서 사용하는 도구의 어댑터 선택 (Claude Code / Codex / OpenClaw / 기타 호스트)
2. 스니펫을 해당 도구의 진입점 파일(CLAUDE.md, AGENTS.md 등)에 붙여넣고 `/path/to/akm`을 실제 경로로 교체
3. 끝. 에이전트에게 지식 저장·조회를 시키면 `99-system/ROUTER.md`의 분류 트리를 따라 동작합니다

클론 폴더를 Obsidian 볼트로 바로 열어도 됩니다. 로컬 `.obsidian/` 앱 상태는 기본적으로 gitignore 처리됩니다.

기존 Markdown/Obsidian 볼트를 AKM으로 통합할 때는 일괄 복사하지 않습니다. 폴더→레이어 매핑을 먼저 고정하고, 대표 자료 한 묶음을 옮겨 링크·lint·검색 인덱스를 검증한 뒤 통과한 방식만 단계적으로 확장합니다. 상세 절차는 `99-system/MIGRATION.md`를 따릅니다.

## 저장 규칙 요약

- **Memory(40)**: 짧고·안정적이고·반복 필요하고·매번 먼저 알아야 하고·포인터로 충분할 때만. 긴 지식 금지
- **Knowledge(20)**: 다시 읽을 가치, 여러 프로젝트 재사용, 도메인 지식
- **Procedure(50)**: 반복되고·절차 있고·실패 지점 있고·검증법 있을 때만
- **Evaluation(70)**: 반복될 수 있는 실패, 품질 기준
- **Action(60)**: 재현·검증·인수인계용만 선별 저장

레이어에 저장되는 개인 지식은 gitignore 처리되어 추적되지 않습니다 — 클론 후 사적으로 사용하면서 시스템 업데이트만 pull 받을 수 있습니다.

OKF 호환 export: 내부 AKM schema는 유지하고 외부 공유용 bundle만 OKF 형태로 내보냅니다. `node scripts/export-okf.mjs --out dist/okf` 후 `node scripts/lint.mjs --okf-export dist/okf`로 검사합니다. 세부 규칙은 `99-system/OKF-COMPAT.md`.

검증: `node scripts/lint.mjs --akm`, `--links`, `--secrets`, `--okf-export <bundle>` — 스키마·enum·레이어 배치·깨진 링크·INDEX 정합성·시크릿 패턴·OKF export 품질 검사. v0.3의 `--task-contract`, `--instructions`, `--routing-failure`, `--prompt-assets`는 실행 계약·지시 우선순위·라우팅 실패·프롬프트 자산 수명주기를 읽기 전용으로 검사합니다. 관리 노트는 전체 스키마를 따르며, 수정하지 않는 `10-sources/` 원본과 불투명한 `80-outputs/` 산출물은 AKM frontmatter를 생략할 수 있습니다. 단, `akmLayer`·`akmType`·`akmRole` 중 하나라도 쓰면 전체 스키마를 충족해야 합니다.

스크립트 lint는 결정론적 구조 검사이며, 결과가 실제 요청을 충족했는지 또는 출처가 claim을 실제로 지지하는지는 판정하지 않습니다. Tier 1 이상에서는 `99-system/VERIFICATION.md`의 request-fit·claim-support 검증을 별도로 적용합니다.

v0.3의 `99-system/EVIDENCE-SCHEMA.md`는 검색 후보·직접 읽기·명명된 claim 지원·충돌을 분리하고, `99-system/TASK-CONTRACT-SCHEMA.md`는 산출물·정본 경로·소유자·실패 처리·readback·최대 실행시간을 고정합니다. 두 계약 모두 운영 볼트에서 검증된 범용 요소만 승격했으며, 장치·백업·개인 저장소·특정 에이전트 정책은 공개 코어에 포함하지 않습니다.

대용량 오디오·영상·PDF·슬라이드는 텍스트 볼트 밖의 별도 에셋 루트에 두고 AKM 상대경로 구조를 미러링합니다. 상세 규칙은 `99-system/EXTERNAL-ASSETS.md`, 보안 규칙은 `99-system/SECURITY.md`를 따릅니다.
