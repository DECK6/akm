# 모든 AKM 스킬이 공유하는 계약

## 세 가지 층위

- **AKM 운영 구조:** 원문, 재사용 지식, 사용자/프로젝트 맥락, 운영 기억, 절차, 실행, 평가, 산출물의 저장 위치와 수명주기.
- **온톨로지:** 무엇이 같은 개념인지, 어떤 종류의 대상끼리 어떤 의미로 연결되는지, 조건과 근거는 무엇인지.
- **LLM 위키:** 질문에 답할 수 있도록 여러 근거를 연결하고 설명한, 사람이 읽고 에이전트가 재사용하는 노트.

저장 폴더를 개념 종류로 쓰지 않는다. 링크가 있다는 사실을 관계가 참이라는 근거로 쓰지 않는다. 위키에 서술됐다는 이유만으로 온톨로지의 가설을 검증된 사실로 승격하지 않는다.

신규 AKM·온톨로지·LLM 위키 구축은 모두 [시작 라우팅](start-routing.md)으로 시작 인터뷰에 연결한다. 모델·노트·자료·질의·검수·확장·교정을 다루는 역할은 [연결된 지식 계약](linked-knowledge.md)을 읽고 같은 정본과 변경 루프를 사용한다. 연구의 근거는 [연구 통합](research-foundations.md)에서 필요할 때 확인한다.

후속 확장·연결 보완·자동 운영은 [지속 운영 계약](lifecycle.md)을 적용한다. `akm-maintain`이 허용된 역할과 예산으로 실제 사이클을 수행하고, `akm-lint`의 구조 검사와 `akm-review`의 의미/질문 검증을 구별한다. 스킬을 설치한 사실만으로 백그라운드 운영이 활성화되지는 않는다.

## 작업공간과 범위

스킬의 상대 링크는 현재 작업 디렉터리가 아니라 **읽고 있는 SKILL.md/참조 파일의 위치**에서 해석한다. 직접 설치 링크는 실제 경로로 해석하고, `skills/<역할>/`의 두 단계 위를 패키지 루트로 삼는다. 공통 스크립트는 그 루트의 `scripts/`에 있다. Claude 플러그인에서는 제공된 플러그인 루트도 사용할 수 있다. 설치/캐시 폴더는 절차의 위치이며 사용자 지식의 저장 위치가 아니다. 스크립트는 실제 절대 경로로 호출하고 지식 루트는 별도로 전달한다. 상대 경로 예제의 실행 기준은 해당 문서에서 확인한다.

1. 사용자 지시와 현재 도메인을 먼저 확인한다. 직업, 언어, 숙련도, 조직, 개인 경력, 경로를 패키지의 기본값으로 가정하지 않는다.
2. 실제 지식 공간의 INDEX와 지침에서 도메인 브리프·모델·상태 경로를 찾는다. 이전 답과 정정은 읽되, 다른 사용자/도메인의 내용은 동의 없이 섞지 않는다.
3. 기존 AKM이 있으면 그 INDEX·ROUTER·SCHEMA·LOOP와 사용자 변경 지시가 기준이다. 다른 템플릿으로 덮어쓰지 않는다. 새 공간은 `akm-structure` 인터뷰에서 인박스·지식 깊이·운영 범위를 선택한 맞춤 프로필로 만든다. [작업공간 규약](workspace.md)의 모든 층이 필수는 아니다.
4. 실행에는 필요한 자료만 읽는다. 전체 볼트·모든 스킬·모든 출처를 매번 로드하지 않는다. 연결 도구가 없으면 파일과 키워드로 작업할 수 있다.

## 분야에 맞춘 질문

심층 탐색에는 [발견 대화 규약](discovery.md)을 적용한다. 일반적인 설문에서 분야 이름만 바꾸지 않는다. 사용자의 실제 용어, 다루는 대상, 결과를 판단하는 기준에서 질문을 만든다.

- 질문은 관련 쟁점별 묶음으로 제시한다. 예: 하나의 실패 사례를 둘러싼 경위·판단·변수·반례·숨은 규칙을 함께 묻는다.
- 답변이 새 가지를 만들면 후속 묶음으로 더 깊이 들어간다. 형식상 노트를 만들 수 있다는 이유로 탐색을 조기에 닫지 않는다.
- 사용자가 더 생각나지 않는다고 밝히거나 정리/중단/건너뛰기를 요청하면 그 신호를 따른다. 부분 주제의 “모르겠다”와 전체 탐색 종료를 구분한다.
- 사용자 응답이 없는 상태는 포화나 동의가 아니다. 그 답을 기다리는 동안 독립적인 정리만 할 수 있다.
- 기존 질문의 단순 조회, 자료 편입, 파일 수정에 심층 인터뷰를 무조건 선행시키지 않는다. 요청된 역할에 필요한 빈틈만 묻는다.

## 근거와 의미

한 작업공간에서 안정적인 ID를 쓴다. 기존 ID 체계가 있으면 유지한다.

| ID 예시 | 의미 |
|---|---|
| D001 | 도메인/범위 |
| Q001 | 답하려는 질문과 유래(user / llm-recommended) |
| S001 | 읽은 자료 또는 인터뷰 진술의 출처 |
| T001 | 대상 종류 |
| C001 | 정의된 개념 또는 개별 대상 |
| R001 | 관계의 뜻·방향·허용 종류·조건 |
| A001 | 대상 사이의 구체적인 관계 주장 |
| N001 | 지식 노트 |

자료의 발견과 읽기를 구분한다. 출처에는 실제 위치, 읽은 범위, 확인 날짜, 필요한 발췌를 남긴다. 사용자 진술에는 대화의 필요한 발췌를 남기고 없는 말을 만들어 넣지 않는다.

**근거 성격:** `source-supported`(읽은 자료가 지지), `user-stated`(사용자 진술), `llm-proposed`(LLM 해석/가설). **현재 상태:** `current`, `needs-review`, `disputed`, `deprecated`. 둘은 독립이다. 현재 사용되는 설명도 검증 전일 수 있고, 출처가 있는 주장도 충돌할 수 있다.

합성 예시는 synthetic으로 표시한다. 교육용 예제를 실제 사용자 경험으로 저장하지 않는다. LLM 설명을 독립적인 출처로 순환 인용하지 않는다. 최신성·고위험 판단이 필요한 주장은 적절한 자료로 확인하거나 답의 범위를 제한한다.

## 저장과 변경

- 새로운 지식은 환경의 맞춤 프로필과 분류 규칙을 거쳐 정본 위치로 저장한다. inbox가 선택됐으면 접수 후 분류하고, 없으면 즉시 분류하며 미정 항목을 추적한다. 원문은 보존한다.
- 기존 노트는 현재 파일을 읽고 필요한 부분만 수정한다. 출처·사용자 정정·유효한 내용을 보존하며 이름과 ID를 재사용한다.
- 같은 개체 여부와 같은 문서로 묶을지 여부는 다른 결정이다. 근거 없이 병합하지 않는다.
- 정의나 관계가 바뀌면 영향을 받는 노트·질문을 찾는다. 모두 갱신하지 못하면 실제 노트/색인에 needs-review를 표시한다.
- 삭제·게시·외부 전송은 해당 환경과 사용자의 범위를 따른다. 기본 지식 구축은 유료 API, 그래프 DB, 원격 저장소를 요구하지 않는다.

## 인계와 완료

공통 상태에는 실제 경로, 현재 역할, 완료한 작업, 근거, 열린 질문, 다음 동작만 남긴다. 장문의 인터뷰·지식 본문은 정본 문서에 둔다. 계획은 실행 증거가 아니다.

각 역할은 자신의 완료 조건으로 검증한다. 구조 검사, 사실 확인, 실제 질문에 대한 효용을 구별한다. 파일을 다시 읽고 실제 링크와 ID를 확인한다. 파일 도구가 없으면 파일별 본문과 상태를 대화로 전달하며 미저장이라고 명시한다.
