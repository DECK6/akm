# AKM Lint — 연결된 지식의 실행 가능한 검사

[공통 계약](../akm/references/contract.md)과 [검사 연결표](../akm/references/audit-map.md)를 읽는다. 현재 도메인·개정·검사 범위를 고정한다. 검사는 기본적으로 읽기 전용이다.

## 실제 검사

기존 형식의 정본을 읽고 최신 연결표를 사용한다. 연결표가 없으면 실제 모델/노트에서 최소 투영을 만든다. JSON 형식으로 기존 원문을 이주시키지 않는다. 검사만 요청받았으면 허용된 실행/임시 위치에 투영을 두고 정본은 변경하지 않는다. 수동 검사만 가능한 환경이면 실행하지 않은 스크립트를 통과했다고 보고하지 않는다.

Python 3.10+에서 패키지의 `scripts/knowledge.py`를 실행한다. 심볼릭 링크를 해석한 SKILL.md의 실제 디렉터리에서 `../../scripts/knowledge.py`를 찾을 수 있다. `lint`, `coverage`, `frontier`, `impact`의 입력과 예제는 검사 연결표 문서에 있다.

- `lint`: 중복/없는 ID, 파일·일반 Markdown 링크, 관계 양 끝의 종류, 출처 읽기/구절 위치, 폐기 참조, 지식-모델 연결, 파일 해시의 신선도.
- `coverage`: 정해 둔 질문의 답 노트와 현재 개정의 정상·반례·미확인 검사 기록. 비어 있거나 미검증인 시스템은 완결되지 않는다.
- `frontier`: 지적에서 파생한 탐색·연결·검수 작업 후보. 기존 backlog와 병합한다.
- `impact`: C/R/A/S 변경에서 영향을 받는 주장·노트·질문까지 추적한다.

## 보고와 수정 인계

검사 오류, 추가 검토 신호, 실제 의미 검증 결과를 나눈다. 해시가 달라지면 정본을 읽고 연결표를 다시 추출한다. 해시만 바꿔서 녹색으로 만들지 않는다. 출력의 `verified_question_ids`는 제출된 검사 기록의 존재를 뜻하며 스크립트가 답의 사실성을 판정했다는 뜻이 아니다.

빠진 탐색/매핑 연결은 `akm-connect`, 미답변·근거 부족은 `akm-explore`, 새 자료 반영은 `akm-ingest`/`akm-grow`, 의미·모순·추론·도메인 완결성은 `akm-review`로 넘긴다. 수정까지 요청받았으면 실제 수정 후 같은 범위를 다시 검사한다.

일반 Markdown 경로 검사를 모든 Obsidian/RDF/OWL 문법 검증으로 부르지 않는다. 연결표 밖의 파일, 의미 모순, 출처의 진위, 형식별 추론 제약은 별도 본문/도구 검토가 필요하다. 검사를 못 한 차원은 `not-tested`로 남긴다.
