# AKM Query — 근거로 답하고 사용하기

[공통 계약](../akm/references/contract.md)을 읽는다. 질문에 답하는 작업은 기본적으로 읽기 전용이다. 저장·확장·정정을 요청받았거나 기존 범위에 포함된 경우에 해당 역할로 넘긴다.

## 질문을 실제 도메인에 맞추기

도메인 브리프와 사용자의 현재 상황을 읽는다. 같은 단어라도 질문의 대상·시점·조건이 달라 답이 바뀌면 필요한 조건을 묶어서 확인한다. 이미 있는 맥락을 되묻거나 단순 질문에 포괄적인 인터뷰를 강제하지 않는다.

## 검색과 읽기

1. INDEX와 활용 질문에서 관련 N/C/R/A를 찾는다.
2. 해당 노트와 정의·관계의 방향·조건·상태를 읽는다. 키워드/의미 검색 도구가 있으면 쓸 수 있지만 특정 제품은 필수가 아니다.
3. 결론을 좌우하는 주요 주장에 연결된 원출처의 실제 근거를 확인한다. 읽지 못하면 위키가 전하는 주장이라고 한정한다.
4. disputed, needs-review, deprecated인 내용을 현재의 확정 사실로 쓰지 않는다. 반대 근거와 빠진 조건도 찾는다.

경로·ID·고유어로 정본이 명확하면 직접 읽기부터 한다. 의미가 모호하거나 관계 탐색이 필요할 때 해당 검색을 추가한다. 검색 순위와 그래프 이웃은 근거 후보이며 진실성/권위가 아니다. 결론을 좌우하는 필수 근거를 낮은 검색 점수만으로 제외하지 않는다. 링크가 열리는지, 주장을 지지하는지, 질문의 시점과 범위에 맞는지 각각 확인한다.

## 답변

직접적인 답을 먼저 제시하고 필요한 근거·관계·적용 조건을 붙인다. **자료에서 확인한 내용, 사용자 맥락에 적용한 해석, 아직 모르는 부분**을 구별한다. 근거가 없는 연결을 만들어 추론 경로를 완성하지 않는다.

위키가 답을 못하면 검색 실패, 지식 부재, 관계 부재, 상충된 설명 중 무엇인지 구분한다. 일반 지식으로 보충할 수 있으나 위키에서 확인한 것으로 포장하지 않는다. 최신 정보가 필요하면 허용된 검색으로 확인하고 범위를 밝힌다.

기록을 찾지 못했다는 사실로 현실에도 없다고 단정하지 않는다. 접근 불가·미독·낡은 자료·범위 밖을 구별한다. 근거 있는 부분은 답하고 부족한 부분만 보류한다.

## 활용과 인계

사용자가 비교·선택·계획을 원하면 그 사용자의 기준에 대입한다. 결론을 바꿀 조건과 실제로 확인할 수 있는 다음 행동을 설명한다. 외부 실행을 지식 질의의 일부로 자동 수행하지 않는다.

확장을 요청받으면 답을 막은 질문, 기존 노트, 필요한 출처를 `akm-grow`에 넘긴다. 실제 적용 후 결과를 받으면 `akm-learn`으로 이어갈 수 있다. 질의만 수행했으면 파일을 바꿨다고 보고하지 않는다.

답을 막는 빈틈은 구체적인 Q/C/R/A/S와 연결해 설명한다. 탐색/확장까지 허용된 요청 또는 운영 정책이 있으면 [지속 운영](../akm/references/lifecycle.md)에 따라 explore/grow로 이어가고 같은 질문에 다시 답한다. 조회만 요청받았으면 지식을 임의로 수정하지 않는다.
