# AKM Grow — 질문을 따라 지식 확장

[공통 계약](../akm/references/contract.md)을 읽는다. 현재 도메인 브리프·상태·관련 노트·최근 질의의 빈틈·검수 결과를 확인한다. 첫 구축을 반복하지 않는다.

[지속 운영](../akm/references/lifecycle.md)의 위임·작업 상태·예산을 적용한다. 여러 번의 자율 확장/정비는 `akm-maintain`이 조정하고, 이 역할은 한 질문이나 변경 집합을 실제 모델·노트로 반영한다.

## 확장 질문

사용자가 풀고 싶은 다음 질문이 있으면 그것을 중심에 둔다. 추천을 맡겼다면 현재 답을 막는 관계, 반례, 근거가 약한 설명, 다른 상황에 적용할 때 드러나는 차이를 후보로 삼는다. 각 후보에 기대하는 효용·관련 노트·필요한 근거를 붙인다.

새 관심사가 나오면 도메인에 맞춰 사례·기존 판단과의 차이·배우고 싶은 깊이·인접 분야의 연결을 묶어 탐색한다. 깊은 재탐색을 요청했다면 `akm-discover`의 포화 기준을 적용한다. 추천만 요청받았으면 실제 지식 작성이나 조사 완료를 가정하지 않는다.

## 보강인가 새 노트인가

- 같은 질문의 근거/사례/조건이 좋아지면 기존 노트를 수정한다.
- 의미가 다른 개념은 별도 ID로 두고 관계로 연결한다.
- 독립적인 새 질문을 충분히 설명할 내용이 있으면 새 노트를 만든다.
- 기존 설명과 충돌하면 양쪽 근거와 적용 범위를 보존한다.
- 새로 쓸 내용이 없으면 변경 없음이 유효한 결과다.

위키 크기를 늘리는 것을 성과로 삼지 않는다. 초기 3개라는 규칙은 후속 확장에 적용하지 않는다.

## 실행 루프

1. 확장 요청/위임 범위에서 필요한 자료를 읽고 `akm-ingest`로 근거를 편입한다.
2. 바뀌는 개념·관계·주장을 식별하고 `akm-ontology`로 반영한다.
3. 관련 위키를 보강하거나 새 노트를 쓴다. 기존 ID·사용자 정정·원문을 보존한다.
4. 참조를 검색해 영향받는 노트/질문을 수정한다. 남은 항목은 실제 문서와 상태에 needs-review로 표시한다.
5. `akm-query`로 이전에 답하지 못한 질문을 다시 답하고, `akm-review`로 변경 범위를 검증한다.
6. 색인·개정 번호·다음 질문을 갱신한다. initial_note_ids는 그대로 유지한다.

결과는 “몇 편 늘었다”보다 “어떤 질문에 이제 답할 수 있고 무엇이 달라졌는가”로 전달한다. 자료 부족으로 여전히 답할 수 없는 부분도 함께 남긴다.

근거가 아직 없으면 `akm-explore`로 조사한다. 새 지식의 연결이 빠지면 `akm-connect`로 모델/위키 대응과 탐색 링크를 보완한다. 변경 후 `akm-lint`의 impact·lint·coverage와 실제 질문 검증을 수행하고 backlog의 해당 작업에 실제 변경 경로·검증 기록을 붙인다. 확장을 위임받았으면 추천 목록에서 끝내지 않는다.
