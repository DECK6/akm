# AKM Learn — 실행에서 다시 배우기

[공통 계약](../akm/references/contract.md)과 현재 공간의 LOOP를 읽는다. 실제 결과, 당시 사용한 지식/절차, 사용자의 정정부터 확인한다. 에이전트의 자기평가만으로 새 사실이나 영구 규칙을 확정하지 않는다.

## 경험 파고들기

무엇을 하려 했고 실제로 무엇이 달라졌는지, 어느 선택에서 결과가 갈렸는지, 기존 지식의 어느 부분을 믿었는지, 조건이 바뀌어도 같은 교정이 성립하는지 도메인에 맞는 묶음 질문으로 살핀다. 이미 로그와 사용자 설명에 있는 사실은 다시 요구하지 않는다.

## 책임 레이어 찾기

| 발견 | 기록과 교정 |
|---|---|
| 오래되거나 잘못된 설명 | evaluation 근거 → knowledge의 주장/출처 수정 |
| 사용자 의도·범위 오해 | evaluation → context의 해당 범위 교정 |
| 절차를 따랐는데 실패 | evaluation → procedure의 단계/검증 수정 |
| 잘못된 분류/조회 경로 | evaluation → ROUTER/INDEX/역할 인계 수정 |
| 관계 정의나 적용 조건 오류 | evaluation → ontology와 영향받는 wiki 수정 |
| 검증 없이 완료 주장 | evaluation → 완료 기준과 실제 재검증 |
| 반복 사용으로 확인한 좋은 방식 | 근거·적용 조건을 갖춘 procedure 후보 |

일회성 경험을 분야 전체의 법칙이나 모든 사용자에게 적용되는 규칙으로 만들지 않는다. memory에는 매번 필요한 짧고 안정적인 포인터만 둔다. 자세한 지식·실패 기록·절차는 담당 레이어에 남긴다. 기존 memory 구조는 해당 환경의 변경 규칙을 따른다.

## 교정 닫기

실패 현상과 기대를 먼저 기록하고, 원인을 뒷받침하는 근거에 맞춰 최소 범위를 수정한다. 같은 질문/사례를 다시 적용해 교정 효과와 남은 한계를 확인한다. 근거가 부족하면 후보로 남기고 사실이나 검증된 절차로 승격하지 않는다.

정본, INDEX, 필요한 참조와 변경 이력을 갱신한다. 무엇이 어느 레이어에서 바뀌었는지, 어떻게 재검증했는지, 다음에도 필요한 조건은 무엇인지 인계한다.
