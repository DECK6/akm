# AKM — 에이전트 지식관리 스킬 묶음

사용자 각자의 분야에서 쓸 수 있는 지식 시스템을 함께 구축하고 운영한다. AKM은 이 **스킬 묶음의 이름**이며, `akm-structure`가 만드는 **지식 분류·운영 구조**의 이름이기도 하다. 온톨로지는 개념과 관계의 의미를 맡고, LLM 위키는 근거를 종합한 설명과 재사용을 맡는다. 세 역할이 같은 사용자·도메인·근거를 공유한다.

먼저 [공통 계약](references/contract.md)을 읽는다. 신규 구축/재개는 [시작 라우팅](references/start-routing.md)을 적용한다. 현재 요청에 필요한 아래 스킬만 읽고 실행한다. 역할은 워크플로 구분이며 별도 에이전트나 유료 서비스가 필수라는 뜻이 아니다.

| 요청/현재 상태 | 담당 스킬 | 남기는 것 |
|---|---|---|
| 내 분야에서 무엇을 알고 어떻게 판단하는지 깊이 파고들기 | [akm-discover](../akm-discover/SKILL.md) | 도메인 브리프, 탐색 지도, 인터뷰 근거 |
| AKM 지식 분류와 운영 공간 만들기 | [akm-structure](../akm-structure/SKILL.md) | 레이어 매핑, INDEX·ROUTER·SCHEMA·LOOP |
| 개념·대상·관계·조건을 설계/수정하기 | [akm-ontology](../akm-ontology/SKILL.md) | 질문에 대입 가능한 의미 모델 |
| 질문이나 LLM 추천으로 설명 노트 만들기 | [akm-wiki](../akm-wiki/SKILL.md) | 연결된 초기 3편 또는 요청한 지식 노트 |
| 문서·링크·메모·경험을 지식에 편입하기 | [akm-ingest](../akm-ingest/SKILL.md) | 보존한 출처, 주장 대응, 통합 변경 |
| 근거를 따라 답하고 실제 일에 활용하기 | [akm-query](../akm-query/SKILL.md) | 출처·관계·한계가 있는 답변 |
| 구조·근거·질의 품질을 검수/정정하기 | [akm-review](../akm-review/SKILL.md) | 재현 가능한 지적과 수정 검증 |
| 다음 지식을 찾고 기존 지식을 확장하기 | [akm-grow](../akm-grow/SKILL.md) | 질문 중심 확장, 기존 노트 보강 |
| 사용 결과·실패를 지식과 절차로 되돌리기 | [akm-learn](../akm-learn/SKILL.md) | 담당 레이어의 교정과 재검증 |
| 맥락을 저장하거나 다음 세션/에이전트로 이어가기 | [akm-context](../akm-context/SKILL.md) | 필요한 근거만 담은 재개 기록 |

## 처음부터 구축할 때

1. 현재 사용자와 도메인, 자료 접근 범위, 이미 있는 지식 공간을 확인한다. 주어진 정보는 다시 묻지 않는다.
2. `akm-discover`로 시작한다. 답에서 새로운 생각이 나오면 그 가지를 다시 파고든다. **질문 하나씩의 고정 진행이나 몇 차례 뒤 자동 종료를 적용하지 않는다.** 사용자가 더 떠오르는 것이 없다고 말하거나 명시적으로 정리/건너뛰기를 요청할 때 다음 단계로 간다.
3. 같은 도메인 브리프를 `akm-structure`와 `akm-ontology`에 넘긴다. 공개 AKM 코어를 바탕으로 인박스 필요성·지식 깊이·운영층 범위를 인터뷰하고 개인별 프로필로 구성한다. 필요하면 발견된 빈틈을 묶음 질문으로 다시 탐색한다. 기존 환경을 통째로 재구축하지 않는다.
4. `akm-wiki`로 실제 내용이 있는 첫 지식 노트 3편을 만든다. 사용자의 질문을 우선하고, 추천을 맡겼다면 LLM이 목적에 맞는 질문을 선정한다.
5. `akm-query`로 실제 질문에 답해 보고 `akm-review`로 구조와 근거를 검수한다. 그 결과를 `akm-grow`의 후보와 `akm-context`의 재개 기록에 반영한다.

첫 3편은 시스템의 시작이다. 모든 요청을 3편 생성으로 끝내지 않으며, 이미 위키가 있으면 맡은 작업부터 이어간다. 질문에 답하기, 자료 하나 읽기, 특정 개념 수정하기 같은 요청에 전체 구축 절차를 반복하지 않는다.

## 역할 간 인계

인계는 “완료했습니다”가 아니라 **실제 파일 경로, 도메인 ID, 확인한 근거, 아직 열린 질문, 다음 작업**을 전달하는 것이다. 같은 작성자가 역할을 바꿔 수행해도 된다. 다른 역할이 사용자 답을 새로 지어내거나 인터뷰를 다시 시작하지 않도록 공통 상태를 먼저 읽는다.

요청이 여러 역할에 걸치면 목적을 한 문장으로 설명하고 필요한 역할만 이어서 실행한다. 조회에는 쓰기 권한을 덧붙이지 않는다. 설치·게시·동기화 같은 외부 작업을 지식관리라는 이유로 추가하지 않는다.

## 사용자에게 보여줄 것

도메인 탐색 중에는 새로 드러난 쟁점과 다음 질문 묶음을, 구축 중에는 실제로 바뀐 모델·노트와 다음 검증을 보여준다. 완료 시 실행한 역할, 저장한 결과, 검증 범위와 남은 질문을 짧게 전달한다. 도구를 실행하지 않았으면 저장·검증·검색이 완료됐다고 하지 않는다.

온톨로지와 위키는 [연결된 지식 계약](references/linked-knowledge.md)의 같은 ID·정본 정의·주장·출처를 사용하고 함께 갱신한다. 설계 근거와 연구별 반영 위치는 [연구 통합](references/research-foundations.md), 공개 참고는 [출처와 적용 범위](references/provenance.md)에 있다. 이 묶음은 gstack의 역할 분담에서 영감을 받았지만 독립적으로 작동한다.
