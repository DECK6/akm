# AKM Maintain — 에이전트의 지식 운영 사이클

[공통 계약](../akm/references/contract.md)과 [지속 운영 계약](../akm/references/lifecycle.md)을 읽고 따른다. 이 역할이 다른 역할을 실제 순서대로 호출하는 조정자다. 하나의 에이전트가 수행할 수 있으며 추가 모델이나 서비스 설치는 필요하지 않다.

## 현재 상태에서 이어가기

신규 분야를 처음 만드는 요청은 `akm-discover`부터 시작한다. 이미 구축했으면 상태·운영 정책·backlog·최근 검사·변경된 출처부터 읽는다. 설치가 끝났다는 이유로 매번 인터뷰하거나 첫 3편을 다시 만들지 않는다.

사용자가 자동 운영을 맡기면 해당 범위에서 실제 실행한다. 기존 위임을 다시 승인받지 않는다. 모호한 분야/루트/자료 접근처럼 실행에 필요한 정보만 묻는다. 단순 조회/추천 요청은 자동 쓰기로 확대하지 않는다.

## 한 사이클

1. 현재 리비전·정본 위치·허용 역할·자료·예산을 기록한다. 중단된 작업은 작성된 파일과 검사 근거를 먼저 대조한다.
2. `akm-lint`의 구조/coverage/frontier와 실제 질문 결과로 backlog를 갱신한다. 중복 작업과 이미 해결한 같은 지적을 다시 쌓지 않는다.
3. 답에 영향을 주는 항목을 골라 `akm-explore → akm-ingest → akm-ontology/akm-wiki → akm-connect` 중 필요한 역할을 실제 실행한다. 기존 근거만으로 고칠 수 있는 연결은 외부 조사를 거치지 않는다.
4. 변경된 파일·ID·원문 보존과 조회 결과를 확인한다. `akm-lint` 뒤 `akm-review`의 의미/반례 검증을 적용한다. 실패하면 그 변경을 보류/교정하고 독립적인 항목은 이어간다.
5. 검증한 작업만 완료 처리한다. 근거·revision·질문 결과·남은 영향 대상을 저장하고 예산이 남으면 다음 항목으로 간다.
6. 예산 소진, 사용자 중단, 새 근거 없음, 미확정 의존성만 남음, 또는 현재 범위 완료 시 종료한다. 마지막 상태와 다음 작업을 저장한다.

“자동으로 키워줘”에 계획만 작성하고 끝내지 않는다. 새 근거가 없거나 권한/도구가 없으면 실제 시도와 중단 이유를 설명한다. 노트 수를 채우기 위해 빈 지식을 추가하지 않는다.

## 반복 호출과 백그라운드

기본 실행은 현재 호스트의 한 사이클이다. 예약 요청이 있을 때만 호스트의 스케줄러에 동일 루트·도메인·정책·예산을 전달한다. 스킬 설치만으로 상시 프로세스가 생긴다고 말하지 않는다. 등록 도구가 없으면 재호출 가능한 실행 지침을 남기고 예약 미설정을 명시한다. 예약 설정을 실제 등록·조회하기 전에는 자동 실행이 켜졌다고 보고하지 않는다.
