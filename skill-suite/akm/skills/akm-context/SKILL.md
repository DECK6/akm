# AKM Context — 맥락 저장과 재개

[공통 계약](../akm/references/contract.md)과 [상태 규약](../akm/references/workspace.md)을 읽는다. 맥락은 자료를 모두 복사하는 것이 아니라 다음 작업을 정확히 이어갈 수 있는 최소한의 연결이다.

## 저장

현재 사용자/도메인, 실제 목표와 최근 수정, 진행 중인 역할, 확인한 정본 경로, 중요한 근거, 결정과 이유, 미응답/미확인, 다음 작업을 구분한다. 장문의 인터뷰와 지식은 정본 파일로 남기고 상태에는 위치를 넣는다.

발견 대화는 탐색한 가지와 아직 팔 가지, 마지막 질문 묶음, 사용자의 실제 종료 신호를 남긴다. 답변이 없었다는 이유로 포화 상태로 바꾸지 않는다. 초기 노트도 실제 작성한 것만 등록한다.

## 재개

1. 사용자 요청의 현재 범위와 도메인을 확인한다. 과거 목표보다 새 정정이 우선한다.
2. 공통 상태와 INDEX를 읽고 다음 작업에 필요한 정본만 연다.
3. 상태에 적힌 파일이 실제로 존재하고 최신 내용과 맞는지 확인한다. 계획을 완료 사실로 사용하지 않는다.
4. 현재 이해와 이어갈 지점을 짧게 설명하고 바로 진행한다. 이미 답한 인터뷰를 처음부터 반복하지 않는다.

## 인계 묶음

받는 역할, 목적, 실제 입력 경로/ID, 적용 범위, 확인한 것/확인하지 않은 것, 다음 행동을 제공한다. 관련 없는 사용자 정보와 모든 원문을 넣지 않는다. 인계 받은 쪽이 직접 근거를 열 수 있어야 한다.

맥락 도구·검색 도구·특정 에이전트가 없으면 Markdown 인계 기록과 JSON 상태로 충분하다. 역할별로 별도의 기억 정본을 만들어 서로 다른 사실을 유지하지 않는다.

## 검증

다음 작업을 처음 보는 입장에서 경로를 열고 목적·권한·미확인·다음 행동을 재구성해 본다. 누락이 있으면 실제 근거에서 보강한다. 파일 도구가 없는 환경에서는 전달용 상태를 출력하고 저장과 전달을 구별한다.
