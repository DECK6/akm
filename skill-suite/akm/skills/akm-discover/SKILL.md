# AKM Discover — 도메인 발견실

[공통 계약](../akm/references/contract.md), [시작 라우팅](../akm/references/start-routing.md), [발견 대화 규약](../akm/references/discovery.md)을 읽는다. 산출물은 설문 응답이 아니라 그 사람의 분야를 이해하는 **도메인 브리프·탐색 지도·근거**다.

## 시작

이전에 받은 목적·분야·사례·자료와 현재 도메인의 브리프를 읽는다. 분야가 없다면 만들고 싶은 분야, 그 분야와의 관계, 지금 풀고 싶은 일/궁금증을 한 묶음으로 묻는다. 실명이나 직업을 필수로 요구하지 않는다.

“전문가의 지식을 추출한다”는 전제도 고정하지 않는다. 학생의 미완성 이해, 취미의 관찰, 팀의 다른 관점도 출발점이다. 알려진 답은 되묻지 않는다.

## 탐색 루프

매 라운드 다음 작업을 반복한다.

1. 사용자가 실제로 말한 것, LLM이 해석한 것, 아직 빈 곳을 구분한다.
2. 답의 가장 구체적인 장면이나 뜻이 흔들리는 말을 붙잡는다. 중요한 모순이나 숨은 전제가 있으면 직접 지적하되 단정 대신 확인할 차이를 설명한다.
3. 그 장면을 여러 방향에서 파는 질문 묶음을 제시한다. 경위·실제 선택·판단 기준·다른 선택·예외·기록을 함께 물을 수 있다. 개수는 내용에 맞춘다.
4. 답에서 새로 나온 가지는 다음 묶음에서 더 파고든다. 같은 표현의 재질문으로 집요함을 흉내 내지 않는다.
5. 탐색 지도를 갱신하고 아직 열려 있는 가지로 이어간다. 임시 모델은 사고를 돕는 가설로 보여줄 수 있으나, 재료가 충분하다는 LLM 판단으로 대화를 종료하지 않는다.

예를 들어 사용자가 “오래 해보면 그냥 안다”고 하면 그 감각이 처음 생겼던 장면, 실패를 알아채는 신호, 초보자에게 설명한다면 무엇을 비교시킬지, 그 직감이 빗나간 때를 함께 파고든다. 질문의 단어와 판단 대상은 반드시 그 사용자의 도메인으로 바꾼다.

## 마무리 조건

사용자가 더 생각나는 것이 없다고 표현하거나 정리/건너뛰기를 요청하면 발견 대화를 마친다. 특정 주제만 막힌 경우에는 다른 가지를 탐색할 수 있다. 중단 요청은 즉시 존중한다. 답변 대기는 포화가 아니다.

도메인 브리프에 범위·목적·핵심 질문·용어·판단 기준·암묵지·사례·갈등·빈틈을 담고, 탐색 지도에 실제 근거와 종료 신호를 남긴다. 모든 항목을 아는 것처럼 채우지 않는다. 실제 인터뷰 진술은 S-ID로 추적한다.

## 인계와 검증

- `akm-structure`: 어떤 자료·맥락·반복 절차·평가를 구분해야 하는가.
- `akm-ontology`: 어떤 용어를 구별하고 어떤 관계/조건을 표현해야 하는가.
- `akm-wiki`: 사용자가 반복해서 돌아온 질문은 무엇인가.
- `akm-grow`: 아직 풀리지 않은 가지는 무엇인가.

현재 사용자의 말로 브리프를 다시 읽어 설명하고, 실제 정정이 오면 반영한다. 사용자가 말하지 않은 경험, 분야 전체에 대한 무근거 일반화, 사용자가 주지 않은 종료 신호가 없는지 확인한다. 열린 질문과 경로를 공통 상태에 남긴다.
