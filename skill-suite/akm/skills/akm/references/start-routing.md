# 구축 진입과 재개

## 자연어 진입 계약

다음 요청은 모두 **`akm-discover` 시작 인터뷰를 먼저 읽고 실행**한다. 기술 명령어나 슬래시 명령을 외울 필요가 없다.

| 사용자의 표현 | 첫 역할 | 인터뷰 이후 중심 작업 |
|---|---|---|
| “akm 구축 시작해줘”, “내 지식관리 시스템 만들자” | akm-discover | 맞춤 구조 + 연결된 온톨로지·위키 |
| “온톨로지 구축 시작해줘”, “내 분야의 온톨로지 만들자” | akm-discover | 도메인 의미 모델, 위키와 공유할 정의·주장 |
| “llm wiki 구축 시작해줘”, “LLM 위키 만들어줘” | akm-discover | 최소 의미 모델과 연결된 첫 지식 노트 3편 |

영문 `start/build AKM`, `build my ontology`, `start an LLM wiki` 등 같은 의도의 요청도 같다. 이 문서의 목록은 문자열 일치 프로그램이 아니라 의미 기반 라우팅 지침이다. 실제 로딩 방식은 호스트의 스킬 탐색 기능을 따른다.

진입점이 ontology/wiki라는 이유로 발견 대화를 생략하거나 즉시 폴더·용어집·빈 노트부터 만들지 않는다. 해당 하위 스킬이 직접 선택됐어도 이 규칙을 적용한다. `entry_intent`에 요청 중심을 남기며 전체 구축을 요청받지 않은 사용자에게 다른 모든 역할을 강제하지 않는다.

## 첫 응답

이미 주어진 분야·목적·자료·이전 답부터 읽는다. 분야를 모르면 분야, 지금 다루는 일/궁금증, 최근 구체적인 장면을 연결한 질문 묶음으로 시작한다. 분야를 알면 그 도메인의 언어로 경험·판단·예외를 함께 파고든다. 구축 방식(인박스·지식 깊이·운영 범위)도 실제 자료 흐름과 연결해 탐색한다.

3편을 쓸 재료가 모였어도 사용자가 계속 생각을 꺼내고 있으면 대화를 이어간다. 사용자 포화/정리/건너뛰기 신호 없이 구축 단계로 넘어가지 않는다. [발견 대화 규약](discovery.md)의 종료와 재개 상태를 따른다.

## 재개와 명시적 범위

- 기존 도메인에서 “이어서 구축”하면 브리프와 상태부터 읽고 미완료 역할을 재개한다. 종료한 인터뷰를 반복하지 않는다.
- 사용자가 “인터뷰 없이 이 자료로 만들어줘”라고 명시하면 그 지시를 따른다. `user-directed`로 남기며 빠진 의미는 가설/미확인으로 구분한다.
- 충분한 인터뷰 자료를 이미 제공했더라도 포화를 지어내지 않는다. 기존 답을 반영한 후속 묶음으로 이어가거나 사용자의 실제 정리 지시를 따른다.
- “A라는 개념 수정”, “이 자료 편입”, “기존 위키에 질문”은 해당 역할을 수행한다. 신규 구축 인터뷰를 강제하지 않는다.
- 온톨로지만 요청받은 경우 의미 모델과 위키 연결 계약까지 만든다. 위키 본문을 쓰지 않았으면 위키 완료라고 하지 않는다. 위키 구축은 모델이 없을 때 필요한 최소 모델을 함께 만든다.

라우팅은 위임을 의미하지 않는다. 같은 에이전트가 해당 SKILL.md를 읽고 역할을 이어 수행할 수 있다.

## 새 도메인과 구축 이후

기존 지식 공간에서 “다른 분야도 시작하자”는 새 도메인의 discover다. 기존 global PROFILE·원문·다른 도메인은 유지하고 그 분야의 브리프·ID 범위·상태를 추가한다. 생성기로 만든 공간은 workspace.py의 domain-plan/domain-init을 사용할 수 있다. 커스텀 위키는 기존 경로에 수동 매핑한다.

“알아서 지식을 확장해줘/관리해줘”는 maintain, “새 근거를 탐색해줘”는 explore, “누락된 연결을 보완해줘”는 connect, “린트/완결성을 확인해줘”는 lint + review다. 이미 종료한 인터뷰를 다시 시작하지 않는다. [지속 운영](lifecycle.md)에 따라 현재 상태와 허용 범위에서 실행한다.
