# AKM Connect — 빠진 연결 보완

[공통 계약](../akm/references/contract.md), [연결된 지식](../akm/references/linked-knowledge.md), [지속 운영](../akm/references/lifecycle.md)을 읽는다. 실제 노트·모델·출처를 읽고 연결 요청이나 lint/frontier의 후보를 확인한다.

## 연결의 종류부터 구별

| 발견 | 처리 |
|---|---|
| 이미 있는 A를 설명한 N이 매핑에서 빠짐 | 실제 본문을 대조하고 A↔N 대응 복구 |
| 관련 노트가 있지만 탐색 링크가 없음 | 연결 이유와 적절한 절을 찾아 노트 링크 추가 |
| 두 C 사이에 필요한 관계가 빠짐 | R의 뜻·방향·조건·허용 종류와 근거를 확인하고 별도 A 작성 |
| 같은 이름의 두 개체 | 정의·범위·시점 비교 후 동일성 검토; 이름만 보고 병합하지 않음 |
| 분야 간 연결 | 도메인 한정 ID로 참조하고 공통점·차이·적용 한계 기록 |

고립 노트는 검토 신호다. 그래프를 연결하기 위해 임의 관계를 만들지 않는다. “관련해서 읽을 만함” 링크는 인과·동일성·필수 조건 같은 도메인 주장과 다르다. A→B가 있다고 B→A나 A→C를 자동 생성하지 않는다. 역관계·대칭·추이성은 R에 명시된 경우만 적용한다.

## 실행과 종료

1. 후보마다 양 끝 ID, 연결 종류, 설명 또는 근거, 성립 조건, 변경할 실제 파일을 준비한다.
2. 연결 보완이 요청/운영 정책에 포함되면 근거가 충분한 항목은 직접 반영한다. 후보 제안/검토만 요청받았다면 결과를 쓰기 계획으로 남긴다.
3. 근거가 부족한 도메인 관계는 `llm-proposed`로 구별하고 `akm-explore`에 넘긴다. 사용자 판단이 필요하지 않은 경로/매핑 보완마다 승인을 묻지 않는다.
4. 모델·위키·색인에서 같은 ID를 추적하고 변경 영향 범위를 갱신한다. 기존 ID·원문을 보존하며 병합은 대체 ID와 이전 참조를 남긴다.
5. `akm-lint`로 참조·종류·출처·파일을 검사하고 `akm-query`로 이제 통과할 수 있는 실제 질문 경로를 확인한다. 새 의미 주장은 `akm-review`의 반례 검토도 거친다.

어떤 연결을 왜 추가했고 어느 질문이 좋아졌는지, 어느 후보는 보류했는지 남긴다. 링크 수나 그래프 밀도를 품질 점수로 쓰지 않는다.
