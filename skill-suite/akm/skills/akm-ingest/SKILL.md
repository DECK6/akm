# AKM Ingest — 자료를 지식으로 편입

[공통 계약](../akm/references/contract.md)을 읽는다. 현재 도메인·질문·INDEX·ROUTER와 관련 모델/노트를 확인한다. 한 자료를 편입하기 위해 전체 도메인 인터뷰를 다시 시작하지 않는다.

## 입력 읽기

자료가 실제로 접근 가능한지 확인하고 읽은 범위를 기록한다. 파일·URL을 받았다는 것과 읽었다는 것을 구분한다. 읽을 수 없는 부분은 미독으로 남기고 그 자료를 확인된 근거로 인용하지 않는다.

원문을 환경의 규칙에 맞게 보존하며 해석을 원문에 덧쓰지 않는다. 새 자료에는 S-ID, 실제 위치, 읽은 절/페이지/시점, 출처 성격을 남긴다. 인터뷰·경험은 실제 진술과 LLM의 요약을 구분한다.

## 통합 판단

주요 내용을 해당 도메인의 활용 질문과 대조한다. 어떤 C/R/A와 기존 N-ID에 영향을 주는지 명시한다.

- 기존 설명을 지지하면 근거를 보강한다.
- 적용 조건이나 범위를 좁히면 모델의 조건과 관련 노트를 함께 수정한다.
- 같은 용어의 다른 뜻이면 정의를 비교하고 별도 개념/범위를 유지한다.
- 기존 설명과 충돌하면 양쪽 근거·버전·조건을 기록하고 disputed 또는 needs-review로 표시한다.
- 독립적인 새 질문을 답할 만큼 내용이 있으면 새 위키 노트를 만든다.
- 목적과 무관하거나 내용이 중복되면 보존/중복 처리만 하고 억지로 새 노트를 만들지 않는다.

판단이 바뀌는 중요한 빈틈은 사용자 도메인에 맞는 질문 묶음으로 묻는다. 예를 들어 용어의 실제 사용 범위, 기록이 만들어진 조건, 현재 관행과 다른 점을 함께 확인한다. 대답하지 않은 내용을 자료에 써넣지 않는다.

## 반영과 검증

ROUTER에 따라 자료를 분류하고 `akm-ontology`와 `akm-wiki` 지침으로 필요한 변경을 수행한다. 절차라면 procedure, 사용자/프로젝트의 제약이라면 context로 연결한다. 외부 문서의 모든 문장을 무조건 knowledge에 넣지 않는다.

INDEX·출처 장부·상태를 갱신한다. 원문 보존, 출처에서 주요 주장까지의 대응, 관련 노트의 링크와 수정 범위를 실제 파일로 확인한다. 어떤 자료를 얼마나 읽었고 무엇이 달라졌는지 인계하며 미독·충돌·추가 질문을 남긴다.
