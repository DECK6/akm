# AKM Wiki — 지식을 설명으로 엮기

[공통 계약](../akm/references/contract.md), [작업공간 규약](../akm/references/workspace.md), [연결된 지식 계약](../akm/references/linked-knowledge.md)을 읽는다. 신규 구축이면 [시작 라우팅](../akm/references/start-routing.md)에 따라 `akm-discover`부터 수행한다. 도메인 브리프·모델·관련 출처·기존 색인을 확인한다. 모델이 없다면 `akm-ontology`로 질문에 필요한 최소 모델을 함께 만든다. 인터뷰를 요약하는 데 그치지 않고 **실제 질문에 답하는 재사용 가능한 지식**을 만든다.

## 주제 고르기

첫 구축은 실제 내용이 있는 지식 노트 정확히 3개를 만든다. INDEX·온톨로지·출처·상태 파일은 3개에 포함하지 않는다. 사용자의 질문을 우선한다. 질문 하나를 보완적인 세 설명으로 나누거나 여러 질문 중 목적에 가까운 세 질문을 고른다. 같은 답을 제목만 바꿔 반복하지 않는다.

질문이 없거나 추천을 맡겼으면 도메인 브리프에서 가장 도움이 될 질문을 선정하고 LLM 추천임을 밝힌다. 각 선정 이유와 연결할 개념·관계를 적는다. 목표도 모르면 목적·궁금증·활용 장면을 묶어 묻는다. 이미 충분히 설명했거나 추천을 맡겼다면 승인 질문을 반복하지 않는다.

기초 구별·판단/비교·적용 사례는 가능한 조합이지 고정 템플릿이 아니다. 분야별로 맞는 조합을 선택한다. 처음 이후에는 변경된 질문/자료에 필요한 노트만 작성·수정하며 매번 3편을 강제하지 않는다.

## 노트 쓰기

각 N-ID 노트에 다음 의미를 담는다. 모든 노트의 제목과 절 구성을 동일하게 만들 필요는 없다.

- 답하려는 Q-ID와 바로 읽을 수 있는 답.
- 답을 이해하는 데 필요한 설명, 구별, 판단 기준이나 과정.
- 적용되는 조건, 반례/예외, 분야에 맞는 구체적인 사례. 가상 사례는 명시한다.
- 어떤 C/R/A-ID를 어떻게 사용했는지에 대한 자연어 설명.
- 주요 주장 옆의 S-ID/출처 링크, 사용자 진술·자료 근거·LLM 해석의 구별, 미확인과 확인 방법.
- 실제로 존재하는 관련 노트 링크와 연결 이유.

노트 메타데이터에 id, 도메인, question_ids, ontology_ids, source_ids, 현재 상태와 날짜를 남기되 환경의 SCHEMA에 맞춘다. 원문 여러 개를 나열하는 대신 같은 질문에서 일치·보완·충돌하는 설명을 합성한다. 원문은 보존한다.

자료 없이 시작하면 충실한 검증 전 초안을 만들 수 있다. LLM의 설명에 가짜 출처·인용·수치·사용자 경험을 붙이지 않는다. 실제 읽지 않은 출처는 근거로 사용하지 않는다. 출처의 존재와 해당 주장을 뒷받침하는지는 따로 확인한다.

## 위키로 작동하게 만들기

노트마다 의미 있는 다른 노트 연결을 최소 하나 찾아 보고, 전혀 연결되지 않으면 주제 선정이 목적에 맞는지 검토한다. 동일 단어만으로 링크를 늘리지 않는다. 색인에는 질문→노트→핵심 관계를 적고, 기존 노트가 새 설명을 가리켜야 하면 필요한 부분을 갱신한다.

초기 3편을 저장한 뒤 `akm-query` 방식으로 실제 질문 하나에 답한다. 3편 전부를 억지로 인용하지 말고 필요한 노트와 관계만 쓴다. `akm-review`로 링크·ID·근거·내용을 확인하고 initial_note_ids에 실제 3개만 기록한다.

정의와 주장의 정본을 명시하고 모델에서도 관련 노트를 찾을 수 있게 연결표를 유지한다. 위키에서 새 정의·예외가 발견되면 모델에 반영한다. 수정 시 모델의 조건뿐 아니라 설명·예제 계산·답변도 같은 개정으로 맞추며 미완료 동기화는 영향받는 실제 노트에 표시한다.

완료 노트는 설명과 답이 있는 본문이어야 한다. 제목·목차·빈 템플릿은 완성으로 세지 않는다. 노트 경로, 질문의 유래, 검증한 범위와 남은 질문을 인계한다.
