# 실제 질문으로 지식 시스템 평가하기

초기 구축과 중요한 의미 변경에는 사용자 질문의 정상 사례, 조건이 달라지는 반례, 근거 부족으로 일부 답을 보류해야 하는 사례를 확인한다. 도메인에 맞는 기대 답을 실제 원문/사용자 규칙에서 먼저 정한다. 모델이 만든 답을 그대로 정답표로 삼지 않는다.

## 기본 기록

질문, 자료 버전/범위, 모델·노트 개정, 실제 첫 답, 근거 위치, 기대와 다른 문장, 사람/에이전트가 교정한 부분을 남긴다. 간단한 작업은 노트의 검증 절로 충분하며 전용 evaluation 폴더를 강제하지 않는다.

- 내용: 핵심 답이 맞는가.
- 근거: 해당 문장을 실제로 지지하는 구절인가.
- 의미: 역할·상태·관계·동일성을 혼동하지 않았는가.
- 조건: 시점·적용 범위·예외를 유지했는가.
- 불확실성: 모르는 부분만 보류했는가. 근거 있는 부분까지 모두 회피하지 않았는가.
- 운영: 새 정보 반영·검색·사람 확인에 어느 정도 수고가 드는가.

잘못된 권한/조건처럼 큰 영향을 주는 오류는 다른 좋은 점수로 상쇄하지 않는다. 실행하지 않은 시간·비용·정확도를 채우지 않는다. 합성 예제, 새로 재구성한 기준선, 실제 사용 기록을 구별한다.

## 효과 비교를 요청받았을 때

가능하면 같은 질문·원문·모델/설정을 고정해 A 원문만, B 같은 원문+위키, C 같은 원문+위키+의미 모델을 비교한다. 최신 자료를 더 넣은 실험은 갱신 시험으로 분리한다. 앞 단계 정답이 다음 실행에 노출됐는지 기록하고 가능한 경우 분리한다.

첫 답과 교정 후 답을 모두 보존한다. 모델 답변 시간뿐 아니라 자료 찾기·사람 검토·초기 구축·유지 비용도 알려진 범위에서 기록한다. 미측정은 0이 아니다. 모델이 준 확률을 검증된 정확도로 바꾸지 않는다.

설계 때 쓴 질문과 새로운 질문을 나눈다. 이미 공개된 예제를 독립 평가용이라고 부르지 않는다. 작은 시험으로 전체 분야의 성능을 일반화하지 않는다. 평가 결과는 개선할 담당 레이어와 재검증 질문으로 연결한다.
